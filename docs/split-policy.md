# Split Policy & Deterministic Manifests

## 1. Overview & Purpose

This document specifies the split policy, generator-disjoint guarantees, and scale tiers established for **ForenSight Milestone R0 (Task 0.2)**.
The programmatic implementation is located in `forensight.data.split` and exposed through `forensight.data`.

To guarantee reproducibility, experimental clarity, and leak-free evaluation, all splits are defined by deterministic, versioned manifest files. Evaluators and models must consume manifests rather than scanning raw directories directly.

## 3. Generator-Disjoint Guarantee

A fundamental invariant for ForenSight is the **strict generator-disjointness** between the training distribution and OOD test distributions:

$$\mathcal{G}_{\text{train}} \cap \mathcal{G}_{\text{unseen}} = \emptyset$$

Specifically:
- $\mathcal{G}_{\text{train}} = \{\text{sd14}\}$
- $\mathcal{G}_{\text{near\_ood}} = \{\text{sd15}\}$
- $\mathcal{G}_{\text{cross\_generator\_ood}} = \{\text{midjourney}, \text{adm}, \text{glide}, \text{wukong}, \text{vqdm}, \text{biggan}\}$
- $\mathcal{G}_{\text{modern\_external}} = \{\text{flux\_sd3\_modern}\}$
- $\mathcal{G}_{\text{real\_world\_external}} = \{\text{social\_wild}\}$

### Rules & Invariants:
1. **Zero Generator Leakage:** No synthetic image generated by any model in $\mathcal{G}_{\text{unseen}}$ may ever appear in the training or validation splits.
2. **Real Image Separation:** Real images in GenImage originate from ImageNet (ILSVRC2012). While real images across generator subsets share the 1,000 ImageNet semantic classes, exact duplicate sample IDs or canonical file paths between train and test splits are strictly prohibited.
3. **Automated Enforcement:** The helper `assert_generator_disjoint(train_manifest, ood_manifests)` and `validate_no_leakage(train_manifest, test_manifest, check_generators=True)` are built directly into the data pipeline and must be run prior to sealing any experimental manifest.

## 4. Deterministic Scale Tiers

To facilitate rapid development and testing without losing class representation across the 1,000 ImageNet categories, ForenSight establishes three canonical scale tiers:

| Tier | Real / Class Limit | Fake / Class Limit | Estimated SD1.4 Size | Intended Purpose |
|---|---|---|---|---|
| **`smoke`** | $\le 1$ | $\le 1$ | $\le 2,000$ images | Fast smoke testing, CI pipelines, pipeline sanity checks. |
| **`pilot`** | $\le 10$ | $\le 10$ | $\le 20,000$ images | Preliminary experiments, fast architecture iterations, hyperparameter screening. |
| **`main`** | Full valid set | Full valid set | ~320,000 images | Final research conclusions, formal benchmark tables, published results. |

### Sampling Invariants:
- **Class-Preserving:** Subsampling operates per `class_id`, ensuring all 1,000 classes remain represented in `smoke` and `pilot` tiers.
- **Deterministic:** Subsampling uses a seeded pseudo-random generator keyed to `(seed, class_id, label)`. The resulting manifest is guaranteed to be 100% reproducible regardless of raw file scanning order or system environment.
- **Research Integrity:** Conclusions on hypothesis verification, model generalization, or explainability **must** use the sealed `main` manifest tier. `smoke` and `pilot` tiers are strictly development aids.

## 5. Manifest Architecture & Schema

### 5.1 ManifestRecord Schema

Each sample in ForenSight is represented by a `ManifestRecord`:

```python
@dataclass
class ManifestRecord:
    sample_id: str           # Unique identifier, e.g. "genimage_sd14_train_n01440764_10026"
    image_path: str          # Filepath to image (relative or absolute)
    label: int               # 0 = real, 1 = fake
    dataset: str             # "genimage", "genimage_plus_plus", "wildrf", "chameleon"
    generator: str           # Generator ID ("sd14", "midjourney", etc., or "nature" for real)
    split: str               # "train", "val", "in_domain_test", "cross_generator_ood", etc.
    class_id: str | None     # ImageNet synset ID (e.g. "n01440764") or None
    metadata: dict[str, Any] # Arbitrary metadata (e.g. original resolution, JPEG QF, etc.)
```

### 5.2 Manifest Operations

The `Manifest` container provides standard collection and serialization methods:
- **Filtering:** `manifest.filter(split="train", label=1)` or `manifest.filter(predicate=lambda r: r.class_id == "n01440764")`.
- **Pandas Conversion:** `manifest.to_dataframe()`.
- **JSON Lines I/O:** `manifest.to_jsonl(path)` and `Manifest.from_jsonl(path)`.
- **CSV I/O:** `manifest.to_csv(path)` and `Manifest.from_csv(path)` (metadata serialized to JSON strings).
- **Leakage Check:** `manifest.validate_no_leakage(test_manifest)`.

## 6. Manifest Sealing & Storage Protocol

1. Manifests are generated and saved under `data/manifests/` (e.g., `data/manifests/v1/`).
2. Each sealed manifest is accompanied by:
   - Total count of real and fake samples.
   - List of active generators and their sample counts.
   - SHA256 checksum of the manifest file.
3. Raw image files remain strictly read-only (`data/raw/`). Any preprocessing (e.g. bias-mitigation recompression or center cropping) creates a separate, versioned derived manifest and cache directory.
